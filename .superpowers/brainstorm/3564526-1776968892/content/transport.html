Gateway ↔ Service-node transport

Both sides need: bidirectional streams (events + intercom), short RPC calls (manifest/health/invoke), auth, TLS, reconnect, works over VPN + public internet. Pick the wire.

A

gRPC + Protocol Buffers recommended

HTTP/2 streams, bidirectional by default. Well-understood auth (mTLS, bearer). Code-gen for TS from a .proto file makes the manifest literally the schema. Handles reconnect, backpressure, message framing for you.

Pros

  • Streaming RPC is the primitive — fits your event model 1:1
  • Typed contract shared between gateway and node
  • Battle-tested libraries, load-balancer friendly
  • Works over any TCP path (VPN, public, Docker overlay)

Cons

  • Adds a protoc build step
  • Binary wire — harder to eyeball with tcpdump
B

WebSocket + JSON (or MessagePack)

One long-lived WS connection per node. You define a tiny envelope {type, id, payload} and route event types over it. Plays well with HTTP proxies, easy to debug, easy to add a web UI plugin later that talks the same protocol.

Pros

  • Zero code-gen, text-friendly
  • Same transport can serve a future web UI
  • Traverses most firewalls/proxies cleanly

Cons

  • You design your own RPC framing, correlation IDs, flow control
  • No native typing — contract lives in docs or hand-written types
C

NATS (broker between gateway and nodes)

Run a NATS server. Gateway and nodes are both clients; gateway publishes invoke.node42, subscribes to events.session123. JetStream gives you retry/replay for free.

Pros

  • Broker handles discovery, load, replay
  • Nodes don't need reachable addresses — they dial NATS outbound

Cons

  • Adds a required third component to deploy (NATS server)
  • Indirection: you're debugging a broker, not a direct stream
D

Custom raw-TCP protocol

You invent the framing, handshake, auth, backpressure, reconnect, heartbeats, error model. Typed by you, from scratch.

Pros

  • Zero dependencies; total control of wire bytes
  • Educational

Cons

  • You will re-implement poorly what gRPC/WS already solved
  • Every production edge case (half-close, keepalive, TLS renegotiation, flow control) is yours to debug
  • Months of yak-shaving before your first scraper streams
